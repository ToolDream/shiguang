# 拾光自动更新实现计划

> 执行者使用 executing-plans 连续实现、自测与修复，不再派生；不提交、推送或发布。

**Goal:** 每天后台检查、可选正式/测试通道与自动下载，用户点击重启后安全更新；接入已确认的设置设计稿和光点图标。
**Architecture:** 复用 GitHub Releases 和现有便携 ZIP；后台更新模块负责检查、暂存和校验，独立更新助手在进程退出后替换并启动，启动确认失败可恢复旧版本。不增加常驻系统服务。
**Tech Stack:** Nim、C、Leaf Win32、现有 GitHub Actions 发布链。
**Spec:** 本文“已确认设计”，视觉依据 docs/images/settings.svg 与 docs/images/logo.svg。

## 已确认设计
- 默认测试版、自动下载开启；正式通道仅正式版，测试通道也接受更新的正式版。
- 运行期间每 24 小时检查一次，时间持久化；启动/休眠恢复到期补一次。不提供手动检查按钮。
- 关闭自动下载后显示下载按钮，失败允许重试下载；完成后设置与托盘显示重启更新；普通退出不自动安装。
- 切换通道使不再适用的候选失效，下一次定时检查按新通道选择；不自动降级。
- 版本身份/顺序不可仅依赖发布时间或 tag 字符串字典序；正式版 v1.2.3，测试按可信源构建顺序比较，拒绝旧源构建晚完成造成倒退。
- 后台网络不得阻塞 UI；重复操作互斥，有界超时/包大小/重试。
- 使用 HTTPS 和签名更新元数据、SHA-256 校验；未配信任公钥或无签名的历史包不得自动安装。私钥/发布 secrets 由用户或获授权发布操作配置，不读取或生成真实发布私钥。
- ZIP 解压拒绝路径穿越、绝对路径、链接及清单外文件；只替换清单内管理文件。更新 EXE 和随包 DLL；保留配置与用户文件。
- 用户点击重启时先确认没有截图/编辑/保存中的工作。目录不可写不静默提权；失败恢复旧文件，保留可诊断状态；断电后能够识别未完成安装。
- 以新进程启动确认完成安装；跨版本临时备份不得与未知文件冲突。
- 设置常规/软件更新分组、标签左控件右；版本显示真实构建身份，不硬编码设计稿示例。图标落实窗口、托盘和 EXE 资源。
- 首次引入需用户手动安装一次。本任务不提交发布，线上签名配置和真实公开下载链不能虚报已生效。
